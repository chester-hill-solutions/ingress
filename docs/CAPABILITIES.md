# Initial capability evidence

**Date:** 2026-09-29. **Status:** RT-0 diagnostic, not product qualification.

| Capability | Evidence | Limit |
| --- | --- | --- |
| Independent repository | Built-ins-only manifest/lockfile, deterministic tests and import/link checker | No Stow checkout, Go build or provider login needed for core tests |
| Native OpenCode session/admission/wait | Ten real tasks admitted and reached terminal outcomes with opencode/space-bunny-free | Terminal success is not independent task correctness |
| File observation | Real producer/consumer writes observed as content/hash revisions | Unknown authorship, coalesced intermediate writes; no guarded admission |
| First join and intentions | Six deterministic context tests; final real run projects both initial envelopes before first native tool events | Native agents have no self-declared intention hook yet; read locations unknown until correlated events |
| Native live feed | Installed credential-free probe confirms server.connected and selected session events; deterministic filtering/sequence-zero tests | Retained log persistence is off by default. Real task tool events/read barriers observed; live feed has no replay and disconnect leaves a coverage gap |
| Active steering | Native delivered event plus exact projected context ID/text in two live awareness runs; resume:false tests | Delivery established in later runs; provider consumption and causally attributable adaptation remain unverified |
| Decision lane | Deterministic full-context/dedup/coalescing/deadline tests | In-memory shadow receipts; no durable control recovery or Jev evaluation |
| Native interruption | Acceptance API fixture | Native stop fencing, successors and process settlement qualification remain separate |

These small, version-changing diagnostics are insufficient to infer benefit. All assigned setup
failures and real outcomes are retained. Across nine assigned trials, four failed before admission, two baselines failed independent
checks, and three awareness runs passed. Initial runs had no observed notification
opportunity; two later awareness runs did. Every result is retained in the
[diagnostic ledger](diagnostic-outcomes.json), including source fingerprints for the latest run.
The final run observed concurrent execution, a dependency read/change/delivered update,
exact initial and update context projection, and 26 passing independent checks.
These results do not establish reliable comparative benefit or guaranteed write safety.

Observed startup incompatibilities were fixed: the cached model catalog exceeded the
new 4 MiB limit (startup now independently bounded at 8 MiB), and the installed binary
rejects --pure despite earlier source-derived assumptions. Version banners/source
inspection are candidate evidence; actual installed API behavior remains authoritative.

The harness assembles structured context at the initial connection and includes it in
the first task prompt: assigned task, dependency/read basis, current observed revisions,
prior file participants and their last known positions, with uncertainty labels.
Later causal updates use the same envelope. Native message admission, inbox delivery,
and exact ID/text presence in projected conversation context are separate evidence.
Presence does not establish that a provider consumed it or that the agent adapted.
