# Repeated native benchmark pilot

Frozen before the first matrix admission on 2026-09-29. This is a small diagnostic
pilot, not qualification of useful collaboration or cross-harness behavior.

## Matrix

Six executable JavaScript task families: currency contract migration, independent
features in the same file, shared dependency extraction, cache/TTL and concurrent
load behavior, strict parsing/exact formatting, and human requirements versus
untrusted imported notes. Each assigns two useful agents in one shared workspace.
File affinities are not ownership. Agents can edit any fixture code file.

Compare awareness-off with awareness-on (native primary-turn context). Three
repeats per fixture/condition:36 cohorts and72 assigned actors. Fresh seed bytes,
new native sessions, identical per-pair task instructions/TEAM.md, tool permissions,
protected files,180000ms cohort deadline (including setup) and hidden checks.
Seed104729 fixes shuffled fixture order and on/off ordering, not model responses.
There are no rescue or integration prompts after failed checks.

Use the configured OpenCode provider/model, installed pinned2.0.16 binary and
existing credential in memory. Benchmark entry requires explicit --real. Provider
messages, request bodies, credentials and tool outputs do not enter evidence.
Generated code remains in temporary benchmark workspaces for independent checks;
those native session directories are not copied into the repository.

Six independently scheduled cohorts may run concurrently, with both actors in each
cohort admitted together; benchmark scheduling does not serialize the two builders.
Each cohort owns one native host and one global event subscription demultiplexed by
session. Record chronological starts/settlements, concurrent cohort load, native
execution overlap and source fingerprints. Timing reflects this load, not isolated
provider latency. Other account/provider traffic is not measured.

## Conditions and observations

Both arms use identical plugin/file/native observations. Both compile bounded
workspace snapshots; only the on arm injects them into primary-turn system context.
The initial assigned task stays identical. Snapshot refresh observes declared files,
read/write metadata, registered peers and coordinator-assigned intentions; no hidden
expected answer, source content or repair prompt is injected. Context is request-local,
with coalesced publication and temporal/unknown read bases, not atomic file knowledge.

The plugin records bounded context hooks and checks the matching context marker in
provider-bound request serialization in memory. Baseline expects absence, treatment
expects presence. Neither marker proves adaptation. A failed bridge, coverage gap,
unknown serialization or saturated evidence invalidates comparison proof without
removing the assigned outcome. Raw request content is discarded.

No stale-write fence is established. Same-file fixtures permit ordinary overwrites;
current native tools and identical protected-file rules apply in both arms. Notes
remain explicitly untrusted fixture data. The pilot does not force an after-read
change barrier, so native overlap alone does not prove an actionable coordination
opportunity. A later opportunity-controlled held-out evaluation is separate.

## Scoring

- Assignment, admission, native terminal success, final artifact correctness and
  fully compliant completion have separate counts. A correct artifact after timeout
  does not become a successful within-budget completion.
- Time: record setup, active task interval, stop/settlement, independent verification
  and total elapsed. Show all observed outcomes separately from completed-only and
  correct-completed-only medians/ranges. Deadlines are censored completion times.
- Functional correctness: independent tests live outside agent workspaces. All six
  seeds must fail and external reference solutions must pass. Verification runs only
  after confirmed writer stop, with permission-restricted, minimal-environment,
  bounded Node subprocesses. Evaluator failure stays a failure/unknown, not a retry.
- Instruction following: named required-behavior checks, exact protected-file
  integrity, confined declared files, observed process/subagent attempts and observed
  protected-file write attempts. Missing coverage is insufficient proof. Mechanically
  preserved bytes alone do not prove obedience. These are objective task-specific
  checks, not a complete assessment of reasoning or every natural-language instruction.
- Complexity: syntax-valid readable JS bytes, code/nonblank lines, lexical branches,
  function count and brace depth. Nullable lexical ambiguities and explicit file/trial
  denominators. Report all measurable artifacts and independently correct artifacts
  separately. Untouched valid seeds must not be treated as simpler successful code.
  These indicators are not cyclomatic complexity or a composite quality grade.
- Model usage: only available numeric native observations, with missing observations
  marked; no pure inference-compute or zero-cost claim from absent fields.

Every planned row is persisted before model/profile admission. Failed setup,
runtime/provider failure, timeout, coverage loss, invalid artifacts, cancellation and
unrun assignments remain. Stop uncertainty prevents checks and aborts further suite
admission. Persistence faults abort work and require all workers to settle before
terminal reporting. No selective replacement or post-result budget changes.

## Running

```sh
npm test
npm run check
npm run benchmark:real
```

Defaults execute the frozen matrix. Explicit options permit subsequent separately
recorded protocols, for example --repeats=3 --parallel=6 --deadline-ms=180000 --seed=104729.
Output is ignored artifacts/benchmark-<id>/evidence.json and report.md. Report
per-family/condition counts and paired repeat differences with comparison validity.
Three repeats establish pilot variability, not significance or reliable product benefit.

First apparatus verification:132 deterministic tests pass, including14 native-runner
fault tests,19 fixture/verifier cases and10 metric/report checks. No provider is needed
for these package tests. Actual native matrix results are recorded separately.
