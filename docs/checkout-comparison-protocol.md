# Checkout comparison protocol

Version 1, 2026-10-12. Frozen before comparative admission. This is a model-free
mechanism study on the standalone order-workflow lab. It does not establish agent
productivity, deployed latency or RT-1 benefit. Every assigned outcome is retained.

Compare three arms: current product commit/lease rules; block grants with no dependency
expansion; block grants with the validated structural graph and explicit contracts.
The current arm calls the actual `WorkspaceAgent` commit route and `LeaseTable`, using
local memory storage and synthetic identity fixtures. Its start adapter mirrors partial
free-path grants and admits contended workers; it must not become a strict file mutex.
Transport, containers and durable-storage latency are outside this study.

All arms use identical initial bytes, private copies, task edits, schedules, existing
baseline behavior validation and independently held mission checks. Common validation
is an additional control around the current product route: it prevents a weaker
validator from manufacturing a treatment advantage. Blocks/graph use the existing
checkout core and product merge function; the graph arm uses `GraphCheckout`. The
optional AST producer supplies fresh source-bound evidence. Oracles never enter it.

Six workloads: useful independent same-file input handling; independent shared-utility
readers; competing edits to one function; a policy/report dependency whose task reads
its checkout to choose a value; a new import alongside its provider edit; and a valid
callback enhancement with an unresolved target. Each workload has two actors. The
reference applies both tasks on successively updated bases. Independent execution
checks must reject the seed and accept that reference before trial admission.

Three schedules vary acquisition and publication order: forward, reverse, and acquisition
forward/publication reverse. Two repeats produce **108 assignments**, 36 per arm. Arm
execution order rotates within each matched repeat/workload/schedule group. Repeats
measure local timing variability; they are not independent new agent behavior samples.

Each synthetic edit costs 10 virtual work ticks; the deadline is 40 ticks. A failed
submission can obtain a fresh base and reapply its goal, up to three attempts. Conflicting
grants retry only after publication changes the head. Unknown-target and scope-expansion
refusals remain failed tasks; no missing expansion feature is silently implemented inside
the evaluator. No result-based rescue or change of model, patch, checker or budget.

Record whole-mission correctness, first-correct and settlement ticks, submissions,
rejected work, grant waiting, refusals on independently classified tasks, final errors
when all tasks published, and every transition. Behavioral interference is scored by
independent execution, not by counting all simultaneous graph-connected edits as wrong.
Measured setup, policy, graph construction, baseline validation and evaluator costs are
reported separately. Policy time includes nested graph/validation work, so those columns
must not be summed. Virtual ticks are not wall-clock agent completion times. Overall
serial replay runtime also includes checking and artifact I/O.

Write assignments, initial source/contract/checker hashes, implementation fingerprints
and settings before trials. Keep exact sources, candidate ASTs, syntax/behavior/mission
logs and failed/timeout results in a fresh ignored artifact directory. Fake identity
fixtures stay inside the baseline adapter; no credentials, provider context or model
prose are collected. Source repositories are read-only inputs.

```sh
npm run checkout:compare -- --python=/private/tmp/ingress-graphify-venv/bin/python
```

Ordinary tests use Node built-ins. The optional comparison producer needs the pinned
Tree-sitter Python environment already used by checkout qualification.

The next real-agent phase must use a substantial shared mission, the same configured
model and native tool menu in every arm, fresh workspaces, identical acceptance criteria,
fixed integration opportunities and predeclared budgets. Record actual model completion,
first-correct versus settlement time, waiting/rework, usage and cost where available.
Missing usage is unknown. Preserve refusals, coverage gaps, failures and deadlines.
All concurrent actors must be admitted together; queued model work cannot stand in for
concurrent scale. A native working-copy/submission adapter is required before admission;
the deterministic replay is not evidence that this integration exists. Real model trials
remain opt-in and cannot qualify RT-1 from one demonstration.

## Real-agent readiness and proposed mission

The budget question for the next phase is separate from this model-free campaign.
The small proposed pilot has three arms, three repeats, four concurrent actors and a
10-minute cohort deadline. A larger option has six repeats, eight actors and 20-minute
deadlines. Use the user's selected budget; neither option is admitted by this document.
The selected OpenCode model is resolved only at explicit real-run admission, and held
constant across arms. No credential reads are needed to prepare the protocol.

A suitable larger mission is an order-processing upgrade with a common end-to-end goal:
price mixed taxable/exempt carts with integer-cent rounding; support partial stock and
backorders; capture/refund partial fulfillment without exceeding payment; preserve a
versioned persisted order/receipt contract; and render consistent receipt/report outputs.
Include legacy order decoding and migration, independently calculated totals, repeated
SKU aggregation, stock conservation, retry/idempotency, currency mismatch refusal and
new dependency introduction. Assign pricing, inventory, payment/refund and persisted
contract/report concerns to four builders. All builders receive the full mission goal
and identical acceptance requirements; eight roles split those same concerns rather
than adding extra work. Use the same fixed integration opportunities in every arm.

Before freezing native assignments, the seed must fail held checks and an independent
reference must pass. Agent work uses actual private directories and native read/edit
menus. A trusted runner must request/record grants, obtain exact checkout bases, submit
changed bytes, relay machine-readable refusals and renew/release grants. Scope expansion
must either be available or explicitly remain an experimental failure outcome. Verify
that the runner cannot silently publish around the selected arm, and that all owned
sessions stop before final verification. Provider exposure/delivery is separate from
model adaptation; filesystem privacy is not established by directory naming.

At the deterministic campaign checkpoint that native working-copy/grant bridge was
absent. The subsequent native amendment implements it for the bounded experiment.
Existing awareness/squad benchmarks do not exercise `GraphCheckout` and cannot stand
in for this comparison. The original readiness limitation remains part of the
model-free campaign's historical scope.

## Native pilot amendment: DeepSeek V4 Flash

2026-10-12, authorized by the user's request to use OpenCode DeepSeek V4. The local
selected V4 model is `opencode/deepseek-v4-flash`; hold that exact ID constant without
changing saved model settings. Use the small proposed budget: three arms, three repeats,
four actors, ten minutes per cohort. Run cohorts sequentially in rotating arm order,
so each cohort has the same maximum provider/host load. Freeze all nine assignments,
36 actor roles, source/contract/directive/implementation hashes before reading credentials.
A separate two-actor model preflight verifies native file edits in different directories
and confirmed process stop; it is retained and has no comparative benefit claim.

The concrete mission implements mixed taxable/exempt goods and integer-cent tax rounding,
optional partial stock reservation/backorders, compatible persisted v1/v2 orders, and
integrated receipt/report text across the existing 16 modules. Payment still captures the
full order and existing refunds remain against that captured total; no automatic refund
for backorders is added. A reference passes 14 independently graded groups and the
16 public legacy checks. The seed fails the new requirements while passing legacy checks.
Expectations stay in the parent grader; application execution runs in a bounded Node 26
child with read-only filesystem access, no network and no child-process authority.

All four initial native prompts are admitted together in actual separate working copies.
A failed checkout allows private preparation only, consistent with v1 submission
enforcement. Publication still requires a live issued grant. When a deferred grant hands
over different source bytes, the runner resets that actor's copy to the issued base and
requires another native edit turn; it never silently reports stale work as derived from
a new base. Hold copies and every generated candidate under ignored/private trial roots.
No shared-folder awareness benchmark substitutes for this bridge.

Each actor gets at most three native turns within the same cohort deadline. Only the
actual refusal (including unknown dependency/scope violations) and current published
source are returned. No held acceptance results, reference code, manual repair or extra
integrator is supplied. Unimplemented scope expansion stays a refusal. Unresolved method
calls and unsupported parser syntax retain the current graph policy; no treatment-specific
source restrictions or parser fixes are introduced after admission. All arms use identical
native model menus and legacy validation; the arm controls publication only.

Record original grants, private preparation, model-turn admissions/terminal states,
refusals, fresh-base retries, actual grant waiting, first observed correct publication,
final correctness after writer/process stop, native execution peak, stream gaps and
closed-step usage and separate final native database totals. First-observed correctness is a sampling bound, not exact creation
of correctness. Native reported cost is not a billing reconciliation; missing usage stays
unknown. The bridge trusts local operator identity/clock and in-memory state; authenticated
durable product grants and an OS filesystem privacy claim remain outside this pilot.

```sh
npm run checkout:agents -- --plan --python=/private/tmp/ingress-graphify-venv/bin/python
npm run checkout:agents -- --real --python=/private/tmp/ingress-graphify-venv/bin/python
```

Plan mode reads no credentials or model runtime. Real mode is opt-in, preserves every
planned assignment and result, and stops its owned server after each cohort. This pilot
still does not qualify RT-1 usefulness or performance on arbitrary repositories.


The first three native preflight attempts failed at the provider boundary; their
[retained outcome](checkout-native-results.md) admits no comparative cohort. The local
bridge/grader readiness work is complete for this bounded experiment; provider
availability and the then-pending variant choice gated actual comparison. An explicit
`--model=deepseek-v4-pro` is supported for a separately authorized fresh assignment set.


The user then selected **DeepSeek V4.1 Flash** (`opencode/deepseek-v4.1-flash`). It uses
fresh assignments and the same small pilot controls/budget. Keep all V4 preflight
failures separately; do not mix the two models in a comparative row. The explicit
CLI `--model=deepseek-v4.1-flash` applies only to this fresh local runtime, preserving
saved user settings. Its successful runtime preflight still gates trial admission.

The V4.1 campaign subsequently passed preflight and completed all nine assignments.
See [results and retained limitations](checkout-native-results.md). This completion

## Expansion follow-up amendment

The user agreed to the next prototype increment after the V4.1 pilot. A fresh
model-free campaign keeps the six missions, three schedules, two repeats, budgets,
legacy validator and held behavior checks. Both scoped arms explicitly request
introduced helper/import blocks after scope refusal. Existing providers become
candidate-derived dependency protections in the graph arm, without an implicit right
to edit them. Expansion checks base and proposed ranges, active conflicts and exact
candidate bytes atomically. A head change requires a fresh checkout/edit attempt;
unknown relationships remain refusals. All expansion attempts, initial refusals and
resubmissions are retained. The current arm is unchanged.

The producer additionally qualifies two runtime intrinsics, contained named helpers
and single-parameter arrows against nine new adversarial binding cases. It does not
infer arbitrary receiver methods or resolve the unknown-callback workload.

The first follow-up replay overlapped full-suite merge mutation tests and was stopped
as invalid apparatus with its 108 assignments and 18 completed outcomes retained.
The second completed all 108 and its 14 recorded fingerprints verified. A subsequent
template-literal blank-line authorization regression tightened scope enforcement;
the final campaign uses a fresh assignment/fingerprint set after the 867-test suite
and producer qualification finish. Earlier campaigns and native outcomes remain fixed.
This amendment admits no new native cohort or benefit claim. A varied-mission native
comparison needs its own qualified references and frozen protocol using V4.1.
