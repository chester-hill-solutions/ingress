# Research mission qualification

Two frozen workloads exercise coordinated evidence work without representing synthetic observations as real science. Each supplies one complete goal, eight complementary workstreams, protected inputs, four shared deliverables and declared dependency edges. Role paths indicate interests, never ownership or write claims. A smaller roster must still complete the same full goal; a larger roster receives no additional acceptance requirements or hidden repair hints.

`fixtures/missions/research.mjs` exports `researchMissions` and `verifyResearchMission(id, root)`. Only `fixture.files` and task instructions belong in the submitted workspace. The grader module and test references remain outside it. Research grading uses the trusted parent's confined JSON/text readers, not submitted executable code. `src/mission-verifier.mjs` performs exact protected-file and manifest checks before and after evaluation. Neither mission needs packages, external model calls or live browsing during execution.

## Synthetic systematic review

`synthetic-systematic-review` contains 18 records. Ten corrected primary randomized cohorts support the stipulated primary calculation. Follow-up, superseded and secondary publications introduce duplicate-participant hazards. Observational records, a different setting, a different endpoint and incomplete denominators require distinct treatment. The outcome is entirely fictional: quiet queued notifications versus immediate interruptions. All records explicitly carry synthetic provenance.

The eight streams cover eligibility, cohort identity, effects, bias, resource analysis, decision policy, cross-file consistency and report synthesis. Shared dependencies link the evidence ledger to aggregate analysis, the analysis and budget inputs to decisions, and all outputs to the final dossier. Six strata and six value/budget cases expose opposing effects and adverse economics. This is a prescribed crude binomial calculation, not a production meta-analysis or an empirical estimate of collaboration benefit. Cohort costs have no demonstrated transfer to future deployment.

Nineteen named checks validate complete eligibility/exclusion, exact assigned denominators, the corrected report, individual effects, aggregate sums, standard errors, nominal intervals, limitations, opposing evidence and every budget decision. A separate report check validates length, basic anchors and obvious contributor metadata. Successful structured checks do not establish scientific validity beyond this controlled fixture.

## Frozen primary-source audit

`primary-cache-evidence-audit` is a standards evidence audit, not a cache implementation exercise. It combines 19 original, concise curated assertions, 14 vendor claims, three apparent conflicts, 12 application cases and three resource forecasts. Its primary corpus was read from RFC Editor on 2026-09-29:

- [RFC 9111, HTTP Caching](https://www.rfc-editor.org/rfc/rfc9111.html), published June 2022, Standards Track.
- [RFC 9110, HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html), published June 2022, Standards Track.
- [RFC 5861, HTTP Cache-Control Extensions for Stale Content](https://www.rfc-editor.org/rfc/rfc5861.html), published May 2010, Informational.

Each assertion preserves its document, section, direct primary URL and `curated_primary_assertion` classification. The bounded corpus comprises paraphrases rather than complete RFC snapshots; no claim is made that all relevant text or current errata are included. Assertions were manually checked against the cited primary sections. Requalification is required if the corpus, interpretation or grading relations change.

The eight streams cover source provenance, entailment, conflicts, applicability, resource forecasts, rollout planning, consistency and dossier editing. They must distinguish normative evidence from empirical gateway results and keep unmeasured performance/security claims unknown. The input vendor note is explicitly untrusted evidence. Resource calculations are hypothetical conditional forecasts, with adverse cost cases retained and no inferred latency quantile.

Thirty-six named checks compare structured claims with trusted semantic relations, not merely existing citation IDs. Correctly identifying a source's topic is insufficient: its assertion must support the verdict in the stated scope. Required support is bounded to the relevant assertion set, with equivalent sufficient citations accepted where the corpus supports them. The grader also checks conflict relations, application actions, forecast arithmetic and rollout uncertainty. This oracle measures correctness against a curated interpretation, not universal standards conformance or source exhaustiveness.

## Independent tests and human review

Run `node --test test/mission-research.test.mjs`. Eighteen independent tests cover contract bounds, incomplete seeds, explicit test-only reference outputs, protected corruption, duplicate cohorts, success-only denominators, excessive certainty, infeasible budgets, negative economics, unrelated citations, unsupported empirical claims, historical conflicts, wrong scopes, invented quantiles and malformed output. Valid reference solutions exist only in that test file and are never exported or included in the seed.

Both reports require neutral presentation without actor/model/team metadata. The automated identity filter catches a limited set of obvious leaks; it is not an anonymization guarantee. The runner must assign blind identifiers and withhold contributor identity, team configuration, run timing, runtime/model cost and automated scores until human judgements are locked. Hypothetical scenario economics are part of the research deliverable and remain visible. Matched configurations receive the same source corpus, directive and deliverable scope.

The machine grader does not determine narrative elegance, exhaustively parse free-form prose or verify every natural-language entailment in a report. It validates the structured evidence claims and basic report anchors. Human judges should check report-to-ledger consistency, source interpretation, handling of counterevidence, clarity, uncertainty and decision usefulness before seeing automated outcomes. Preserve all assigned runs and all failed checks; passing arithmetic cannot erase a failed functional or integrity check. These missions qualify a repeatable workload, not a demonstrated product benefit.
